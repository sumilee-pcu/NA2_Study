# 실기 3영역 및 문제풀이 PRD

버전 0.3 · 결정일 2026-10-23 · 대상: NA2-study

## 목적과 이번 범위

실기 학습을 **작업형 / 실습형 / 단답형·객관식**의 세 영역으로 나눈다. 학생이 실제 제작, 설정 실습, 지식 확인 중 무엇을 연습하는지 구분할 수 있도록 한다. 이는 학습센터의 분류이며 공식 시험의 문제 수·배점·시간을 새로 확정하는 규정이 아니다.

실기 24문항의 답안 입력·문항별 채점·해설·오답 복습·학습 기록을 유지하면서 **Windows·라우터 실습 자료 8개와 입력값 확인 44개**를 추가한다. 기존 작업형 케이블링은 계속 사용할 수 있다. 실습 자료의 입력·판정·풀이 참고 여부를 별도로 저장한다. 백업 가져오기·모의시험·타이머·Windows Server 자체 시뮬레이터·라우터 시뮬레이터 구현은 포함하지 않는다. 검수 후 사용자 요청 범위에서 커밋·배포한다.

최상위 메뉴는 학습센터·필기 문제풀이·실기이다. 실기 안에서 세 영역은 같은 수준이다. 라우터는 독립 프로그램으로 개발하고 실습형에서 연결한다. 연결 주소가 실제로 제공·검증되기 전에는 가짜 실행 링크를 만들지 않는다.

기존 케이블링 직접 주소를 삭제하거나 강제로 다른 경로로 바꾸지 않는다. 실기 홈을 경유하지 않고 기존 주소에 들어가도 같은 기능과 기록을 사용할 수 있어야 한다.

## 영역별 제품 역할

| 영역 | 학생이 수행할 일 | 웹에서 제공할 일 | 평가의 한계 |
|---|---|---|---|
| 작업형 | 케이블 준비·배열·절단·삽입·압착·연결 확인 | T568A/B, 다이렉트·크로스 결선, 핀 진단, 제작 절차 | 웹 정답으로 실물의 압착·접촉·링크 성능을 보증하지 않음 |
| 실습형: 라우터 | 문제 대상 장비에 명령 입력·확인·저장 | 4개 과제의 모드·설정·확인·저장 절차, 입력값 점검 20개 | 실제 명령 실행·장비 상태 채점과 구분 |

| 단답형/객관식 | 짧은 답 입력 또는 조건에 맞는 보기 선택 | 검수된 24문항·문항별 채점·해설·출처·오답 복습 | 학습용 판정과 공식 시험의 답안 인정 범위는 구분 |

실습 프로그램은 ICQA 자료실의 최신 안내에서 운영체제·설치 조건을 확인하도록 한다. 오래된 안내에 있는 실행 시간 제한이나 백신 비활성화 문구를 현재의 필수 실행 절차로 그대로 옮기지 않는다. 시험 일정·배점·운영체제 버전 등 변동 가능한 정보에는 확인일과 공식 출처가 필요하다.

## 단답형/객관식 문제 계약

문제 유형은 `short`, `single`, `multiple`로 구분한다. 단답형은 설명에 맞는 용어·약어·주소·명령 등을 짧게 답하도록 구성하며 장문 서술 평가는 포함하지 않는다. 초기 검수 결과인 유형별 8문항, 총 24문항을 사용한다. 이 구성은 세 채점 경로를 연습하기 위한 교육용 구성이며 실제 시험 비율이나 전체 범위를 뜻하지 않는다. 문항을 추가할 때도 기술 근거와 답안을 먼저 검수한다.

| 공통 항목 | 설계 규칙 |
|---|---|
| 식별자·버전 | 문항 ID를 고정하고 문구·답안 변경 시 버전을 남김 |
| 내용 | 주제, 학습 목표, 지문, 유형, 난이도 근거를 기록 |
| 답안 | 단답형 허용 답안 또는 정답 선택지 ID를 명시 |
| 해설 | 정답 근거와 오답의 혼동 지점을 구분 |
| 출처 | 첨부 파일명·PDF 실제 쪽수·대응 내용·보완한 1차 근거·확인일을 기록 |
| 검수 | 원문과의 차이, 수정 이유, 검토 상태, 남은 한계를 기록 |
| 제공 여부 | 검수 통과 문항만 학습용으로 전환; 대기·제외 항목은 집계와 화면에서 분리 |

원본 검수 자료는 `content-review/practical-bank.v1.json`이다. 생성 스크립트가 `reviewStatus: approved`인 24문항만 `src/content/practical-questions.json`으로 변환하며 학생 앱은 변환한 데이터를 사용한다. 생성 시 필수 필드·정답·보기 ID·허용 답안·정규화·출처 참조를 검사한다. 검수 원본과 학생용 데이터를 각각 수작업으로 수정하여 서로 다른 정답을 만들지 않는다. 검토 대기·제외 항목은 실행용 데이터에서 제외한다.

실행용 데이터에는 학습용 채점에 필요한 정답이 포함된다. 화면은 제출 전 정답을 가리지만 브라우저에 전달된 데이터를 비밀로 만들 수는 없다. 감독 시험용 보안으로 표현하지 않으며 검수 보고서나 전체 답안표를 일반 학습 메뉴에 노출하지 않는다.

### 채점 규칙

| 유형 | 판정 규칙 | 주의할 사례 |
|---|---|---|
| 단답형 `short` | 문항별 허용 답안과 동일한 정규화를 입력·답안 양쪽에 적용한 뒤 정확히 비교 | 검수 규칙의 `trim`·`collapseWhitespace`·`caseSensitive`만 적용. 내부 공백 전체 삭제, 접미사 제거, 부분 문자열·유사도 인정, 전각 자동 변환을 하지 않음 |
| 단일 선택 `single` | 선택한 보기 ID 하나가 정답 ID와 일치 | 화면 표시 순서나 번호를 정답 ID 대신 저장하지 않음 |
| 복수 선택 `multiple` | 선택 집합과 정답 집합이 정확히 일치 | 선택 순서는 무관. 정답 누락이나 오답 추가가 있으면 완료로 판정하지 않음 |

단답형에서 승인된 동의어·약어·한글/영문 표기는 문항마다 등록한다. 검수 목록에 없는 표현을 유사하다는 이유로 자동 인정하지 않는다. 학생이 제출 후 정답·해설과 비교해 복습할 수 있게 하되 최초 판정을 조용히 변경하지 않는다. 빈 입력·빈 선택 또는 “모르겠어요”는 `unanswered`로 기록하며 정답으로 처리하지 않는다. 잘못된 선택지 ID나 중복 ID는 유효한 제출로 받아들이지 않는다. 복수 선택은 부분점수를 부여하지 않는다.

### 학습 흐름과 기록

| 이번 제공 방식 | 피드백 | 제출 기록 |
|---|---|---|
| 전체·유형·주제별 연습 | 문항 제출 후 내 답안·판정·정답·해설·PDF 쪽수·1차 근거 링크 제공 | 원래 입력·선택 ID·판정·시도 시각을 보존 |
| 오답 복습 | 가장 최근 제출이 오답·미응답인 문항을 다시 풀이 | 새 시도로 추가, 정답이면 복습 목록에서 해결, 과거 시도·원답안 유지 |
| 이어 풀기 | 새로고침 후 초안·진행 위치·제출 결과 복원 | 같은 제출을 다시 시도로 추가하지 않음 |
| 기록 확인·내보내기 | 시도 이력과 현재 복습 대상을 구분, 백업 파일 제공 | 기존 필기·케이블링 기록과 분리 |

필터의 표시 개수는 실제 대상 문항 수와 일치해야 한다. 문항 제출 전에는 정답·해설을 숨기며 제출 후 같은 시도의 답안을 바꿔 덮어쓰지 않는다. 중복 클릭이나 새로고침으로 시도가 중복 기록되어서는 안 된다. 재풀이는 새 시도이며 기존 결과를 보존한다. 오답 복습 목록은 전체 과거 오답 수가 아니라 문항별 최신 제출로 결정한다. 아직 한 번도 제출하지 않은 문항은 오답 목록에 넣지 않는다.

기존 `na2_study_learning_v1`, `na2_study_written_v1`, `na2_study_cabling_v1`는 변경하거나 초기화하지 않는다. 단답형/객관식은 별도 `na2_study_practical_v1` 키와 스키마 버전을 사용한다. 기록에는 문제은행·문항 식별 정보, 세션 문항 순서와 진행 위치, 입력 초안, 제출 결과와 시도 이력을 포함한다. 새로고침 복원과 백업 파일 가져오기는 구분하며, 이번에는 **내보내기만** 제공한다.

손상된 데이터·지원하지 않는 버전·저장 오류·다른 탭의 변경 충돌을 감지하면 자동 저장을 중단한다. 실패한 기록을 정상 빈 기록으로 덮어쓰지 않고 보존한 원본을 백업할 수 있게 한다. 학생에게 현재 화면 상태와 저장 상태를 구분해서 안내한다.

자동 저장은 UTF-8 5MiB·20000시도까지 허용하며 브라우저 할당량 실패도 처리한다. 메모리 검증·내보내기의 절대 한도는 별도 50MiB·200000시도이다. 저장 한도를 넘겨도 기록을 자동으로 삭제하지 않고 현재 탭의 풀이·제출·전체 백업을 유지한다. 메뉴 이동에서 미저장 상태를 보존하되 새로고침·탭 종료는 백업 안내가 필요하다. 탭 간 변경 감지와 저장 전 원문 비교는 원자적 동시 쓰기 잠금이 아니다.

필기·케이블링 평가가 진행 중이면 기존 평가 차단 정책으로 새로운 문제·해설·오답 기록 화면을 모두 가린다. 직접 주소·새로고침을 통해 진입해도 같다. 정적 웹앱은 내부 학습 흐름을 보호하는 도구이며 감독 시험용 보안이나 다른 탭의 자료 열람 통제를 보장하지 않는다.

모의시험·제한시간·힌트는 후속 범위이다. 향후 모의시험에는 전체 제출 전 정답 차단·시간 복원·만료와 제출의 중복 처리 규칙이 필요하고, 힌트를 추가할 때에는 도움 사용 기록을 분리한다. 현재 연습 기록에 구현하지 않은 힌트 사용이나 시험 소요시간을 추정하여 넣지 않는다.

## 초기 문제은행 검수 절차

1. 원본 PDF를 보존하고 실제 쪽수와 내용·표·그림을 확인한다.
2. 명확히 평가할 수 있는 항목만 문항 후보로 나누고 출처를 연결한다.
3. 계산·용어·명령·설명을 1차 근거와 대조한다. 원문 오류는 수정 이유를 남기고 출제 문구를 바로잡는다.
4. 정답이 여러 해석으로 갈리면 조건을 보완한다. 보완해도 검증할 수 없는 항목은 대기로 남긴다.
5. 정답·허용 답안·보기·해설의 일관성을 확인한다. 새로 만든 오답 보기나 재구성 지문은 자체 작성임을 구분한다.
6. 데이터의 ID 중복, 유형, 정답 참조, 필수 근거·검토 상태를 검사하고 검수 결과를 요약한다.

첨부 자료는 문제 개발의 출발점이며 모든 문장이 공식 확정 정답인 것으로 취급하지 않는다. 자료에 없는 내용을 PDF에서 확인한 것처럼 쪽수만 붙이지 않는다. OCR이 모호하면 원본 화면을 대조하며 판독할 수 없으면 보류한다.

## 변경 파일과 확인 범위

- 정보 구조와 문제풀이 구현: `src/App.jsx`, `src/Practical.jsx`, `src/content/practical.mjs`, 문제풀이 화면·채점·기록 모듈, 관련 스타일·검증 파일.
- 제품 정의: `docs/PRD.md`, 이 문서, `DESIGN.md`, `README.md`.
- 데이터: `content-review/practical-bank.v1.json`을 근거로 생성한 `src/content/practical-questions.json`과 생성 스크립트.
- 검증 기록: `docs/PRACTICAL_QUIZ_VERIFICATION.md`에 이번 변경의 빌드·회귀·화면 검사 결과를 기록.

실제 수행한 검사와 결과는 이번 구현 검증 보고서가 기준이다. 본 문서의 수용 기준은 이미 실행하거나 통과했다는 뜻이 아니다. `PRACTICAL_CONTENT_REVIEW.md`와 `PRACTICAL_VERIFICATION.md`는 초기 검수·메뉴 단계의 이력으로 보존한다. 기존 공개 배포 문서도 이전 버전의 근거이며 이번 변경의 배포 증거로 재사용하지 않는다.
